# Живое демо: добавить / заменить критерий в чек-листе ЗВОНКА и переоценить один звонок

Сценарий контрольного шага: «добавить или заменить критерий через UI, сохранить чек-лист, применить к диалогам».
Чек-лист — `freedom_call_v1` (наследует `freedom_chat_v1`, своё только у 06). Звонок — `p4-ru-001` из группы `DEV`.
Скриншоты сняты playwright при ширине 1440 px (`scripts/demo_live_ui.py`), 0 ошибок в консоли.
Автотест того же сценария (mock-провайдер): `tests/test_demo_live_call.py`.

## Подготовка (до выхода на сцену)

```bash
cd /root/cqa
cp checklists/freedom_call_v1.yaml /tmp/freedom_call_v1.orig.yaml   # оригинал для шага 9
cp results/dev.json /tmp/dev.orig.json                               # результаты группы до демо
git status --short checklists/                                       # должно быть пусто
```
- Сервер: `python -m cqa serve --port 8090`, без `CQA_MODEL/CQA_ENSEMBLE/CQA_JURORS/CQA_JUDGE` (жюри Haiku + Sonnet, судья Opus).
- Для звонка `p4-ru-001` все 8 критериев уже должны лежать в кэше. Проверка: «Переоценить» на карточке звонка
  должно показать `$0` и около 2 с. Если нет, прогоните его один раз заранее.
- В меню «Ещё ▾» флажок **«Без кэша»** должен быть СНЯТ.

Рубрика 09:
```
YES — оператор или IVR сообщил клиенту, что разговор записывается.
NO — о записи разговора не сообщено.
NA — звонок прервался до разговора с оператором.
```

Что сказать по ходу демо:
- Кэш привязан к хэшу критерия: в хэш входят название, тип, рубрика, правила, описание чек-листа, допущения и промпт.
  Вес и `code` в хэш не входят. Поэтому изменённый критерий уходит модели, а остальные берутся из кэша.
  Смена веса — это «Ещё → Пересчитать веса» (без LLM).
- Итог пересчитывается по новому набору весов. 09 (вес 5, «Да») поднимает итог `p4-ru-001` с 43.33 до 47.69,
  то есть с 26/60 до 31/65 применимых баллов.
- В выгрузке v1 новый критерий получает свой код (`recording_notice`; если поле «Код» пустое, используется `09`).
  `python -m cqa validate results.json --allow-custom` проходит и выдаёт предупреждение о нестандартном коде.

## Запасной путь: CLI (если UI недоступен)
```bash
# 1) добавить 09: вставить карточку в checklists/freedom_call_v1.yaml (или PUT /api/checklists/freedom_call_v1)
# 2) переоценить один звонок с кэшем; результат пишется в отдельный файл, results/dev.json не трогается
python -m cqa evaluate --group DEV --ids p4-ru-001 --out results/demo_live.json
# 3) выгрузка v1 и валидация (у остальных 64 диалогов этого прогона будет status:"error" — это нормально)
python -m cqa export --group DEV --run demo_live --format v1 --out /tmp/demo_v1.json
python -m cqa validate /tmp/demo_v1.json --allow-custom
# 4) восстановление
git checkout -- checklists/ && rm results/demo_live.json results/demo_live.csv
```
То же через HTTP (это те вызовы, которые делает UI): `GET /api/checklists/freedom_call_v1` → добавить элемент
в `checklist.criteria` → `PUT /api/checklists/freedom_call_v1 {"checklist": …}` →
`POST /api/evaluate {"group":"DEV","ids":["p4-ru-001"]}` → `GET /api/jobs/{id}` (`meta.usage.calls`, `meta.cost_usd`) →
`GET /api/export/DEV/results.json`.

## Исправлено при подготовке демо
- Кнопка «Переоценить» на карточке диалога всегда работала без кэша (`fresh:true`): все 9 критериев уходили модели.
  Теперь она учитывает флажок «Без кэша» и отправляет модели только изменённые критерии.
- «Редактор YAML» не сохранял чек-лист с `extends` (`checklist needs id and criteria[]`), поэтому вернуть
  `freedom_call_v1` через UI было нельзя. Теперь YAML проверяется в разрешённом виде и сохраняется как есть.
- Поле `code` (код для экспорта v1) входило в хэш критерия, и смена кода заново запускала LLM. Теперь не входит.
  В форме критерия появилось поле «Код».
