# Разметка диалогов людьми (валидация CQA)

Цель — проверить, насколько система совпадает с человеком. **Метки ставят только люди**; инструменты
ничего не подставляют и не показывают ответы модели.

## Что размечаем
- 50 диалогов DEV (`results/human/sample.json`): все языки (RU/KZ/EN), все 5 звонков, разные диапазоны оценок,
  все 5 диалогов с подозрением на грубую ошибку. Список выбран скриптом `python scripts/labeling_kit.py` (seed фиксирован).
- 15 из них — **запечатанный held-out** (`results/human/heldout_sealed.json`). Не открывайте этот файл и не
  обсуждайте эти диалоги при правке промптов/чек-листов. В отчётах они появятся только в самом конце (`--final`).
- Два аннотатора, **A** и **B**, работают **независимо** (не смотрят метки друг друга); порядок диалогов у каждого свой.

## Как запустить (≈ 1 мин на диалог, 50 диалогов ≈ 50 мин)
```bash
source .venv/bin/activate
python -m cqa label --annotator A --sample results/human/session_A.json   # аннотатор B: --annotator B … session_B.json
```
Показывается расшифровка диалога, затем по очереди 8 критериев с **официальным текстом рубрики** чек-листа.
На каждый критерий — **одна клавиша** (Enter не нужен):

| клавиша | значение |
|---|---|
| `y` / `n` | YES / NO (для 08: `y` = грубая ошибка ЕСТЬ) |
| `x` | NA (только если критерий допускает NA) |
| `0`…`4` | позиция на шкале: 04 → `0`=0 `1`=5 `2`=10 `3`=15 `4`=20; 06 → `0`=0 `1`=4 `2`=7 `3`=10 |
| `?` | показать доп. правила критерия |
| `c` | комментарий (необязательно, вводится строкой) |
| `b` | назад к предыдущему критерию |
| Enter | оставить прежнюю метку (при повторной разметке) |

Метки сохраняются после каждого диалога в `data/human/labels_A.json` (папка `data/` не попадает в git — в
комментариях может быть текст клиента). Прервать — `Ctrl+C`; повторный запуск той же команды продолжит с места остановки.

## Правила
1. Оцениваем **оператора-человека** строго по тексту рубрики, а не по «общему впечатлению». Бот и системные сообщения не оцениваются.
2. Сомневаетесь между двумя значениями — нажмите `?`, перечитайте правила, выберите одно и оставьте комментарий `c`.
3. Не открывайте результаты системы (`results/…`), UI с оценками и метки коллеги до конца разметки.
4. NA — только когда рубрика прямо разрешает («не требовалось», «диалог прервался»), а не «не знаю».
5. 08 (грубая ошибка) — `y` только при явной цитате оператора (грубость, оскорбление, разглашение и т.п.).
6. Не тратьте на диалог больше 2–3 минут: время фиксируется (`seconds` в файле меток).

## После разметки
Передайте файл `data/human/labels_A.json` / `labels_B.json` тому, кто собирает отчёт, и запустите:
```bash
python scripts/agreement.py
```
Скрипт посчитает согласие A–B (κ Коэна, взвешенный κ и MAE для 04/06, MAE итогового балла, согласие по грубым
ошибкам), согласие системы с каждым аннотатором и с консенсусом (95% бутстрэп-интервалы), precision/recall грубых
ошибок, и выпишет расхождения. Ячейки, где A ≠ B, попадут в `results/human/adjudicate.json`: разберите их вдвоём и
сохраните итог в `data/human/consensus.json` (тот же формат, что labels_*.json), затем запустите скрипт ещё раз.
Отчёт: `docs/HUMAN_VALIDATION.md`, данные — `results/human/*.json`. Held-out — только в финале: `python scripts/agreement.py --final`.
